# Гібридне кешування витрини CodeCart PRO 3.0.6

CodeCart PRO використовує три незалежні рівні:

1. Сервер (PHP, MySQL/MariaDB, OpenCart) залишається єдиним джерелом цін, залишків, кошика, замовлень, авторизації та персональних даних.
2. Штатний кеш OpenCart (File/APCu/Redis/Memcached) працює окремо й не залежить від браузера.
3. Google Workbox 7.4.1 — **необов'язковий** браузерний кеш публічних статичних ресурсів; **OFF за замовчуванням**.

## Налаштування

Для основного магазину: «Система → Налаштування → Сервер → Кешування Workbox».
Для додаткового: «Система → Магазини → Редагувати → Сервер → Кешування Workbox».
Вмикається лише після ручного збереження. Потрібні HTTPS та повний production-архів із локальними бібліотеками Workbox.

Адміністратор бачить попередження, якщо бібліотек немає. У такому разі запитаний прапорець зберігається, але Service Worker не реєструється. Публічна сторінка працює звичайним способом.

## Кешуються лише

- Публічні JS/CSS з каталогу тем і скриптів **лише з єдиним параметром v=версія**; невірсійовані файли завжди завантажуються з мережі
- Публічні готові зображення з image/cache та статичні картинки тем
- Публічні шрифти теми

Ліміти: 120 версійованих статичних файлів на 30 діб; 160 шрифтів/зображень на 14 діб. Кеш оновлює і видаляє Workbox. Інші кеші браузера й сторонніх модулів не очищаються.

## Ніколи не кешуються

HTML, сторінки товарів і категорій, AJAX/JSON, ціни, залишки, пошукові відповіді, персональні дані, оплата, кошик, оформлення, замовлення, адміністративні маршрути, приватні медіафайли, запити POST та будь-які ресурси з невідомими query-параметрами. Відключення інтернету не створює «офлайн-магазин» і не дозволяє оформити замовлення офлайн.

IndexedDB навмисно не додано: модуль «Нещодавно переглянуті» вже використовує безпечну серверну сесію. Дублювання товарів, ціни та стану кошика на пристрої збільшило б складність і ризик неконсистентності без очевидної користі.

## Технічні деталі

- Статичний root worker: upload/codecart-sw.js. Працює і для інсталяцій у підкаталогах та не захоплює адміністративні чи сторонні маршрути.
- Скрипт реєстрації: catalog/view/javascript/codecart/workbox/register.js підключається **лише в ON** у двох стандартних темах. Сторонні шаблони не змінюються.
- При першій активації зберігається технічний прапорець config_codecart_workbox_used. Після OFF невеликий inline-код очищає **лише** раніше зареєстрований CodeCart worker і його кеш, не зачіпаючи Service Worker інших модулів.
- До першого увімкнення жодний Workbox JS чи реєстрація не додаються в HTML.
- Сайти на різних доменах незалежні; магазини у підкаталогах одного домену отримують різні scope і різні кеші.
- Workbox розповсюджується локально у production ZIP, на сервері магазину Node.js не потрібен.
- Інструмент збірки перевіряє SHA-256 кожного з 7 офіційних файлів Workbox 7.4.1; на клієнті немає CDN-залежності. Архів збирається через tools/package_production.py; Node.js потрібен лише на машині складання.
- Файл codecart-sw.js не потрібно кешувати через Cloudflare: налаштуйте Cache Rule «Bypass cache» для цього шляху. Переконайтеся, що MIME — JavaScript.
- Якщо на тому самому scope вже працює сторонній Service Worker, CodeCart нічого не підміняє. Інтеграція з таким модулем є окремою опцією.

## Перевірки перед релізом

Запустіть node tools/qa_workbox_hybrid.cjs і Playwright E2E. Після увімкнення перевірте Chrome Application → Service Workers, мережеву доступність CSS/JS, оновлення файлів після зміни версії, OFF, два відкриті таби, кошик, оформлення, замовлення, інші теми та мультимагазин. Жодне звичайне оновлення PHP/cron/API не повинне залежати від Workbox.
