# Consent-based cart contact capture (CodeCart / UniShop2)

Sources: three supplied HTML checkout snapshots. The normal and fast CodeCart checkouts request `checkout/guest` via AJAX, so their initial HTML does not contain the eventual contact fields. Both use `checkout/guest/save`. Quick checkout may omit email unless the voluntary cart-recovery opt-in is enabled. UniShop2 renders firstname/lastname/email/telephone directly in `form[name="unicheckout-customer-form"]` and validates through `checkout/uni_checkout/validate`, so it does not call the stock guest/save hook.

With abandoned-cart analytics and guest capture explicitly enabled, CodeCart checkout presents an optional email and recovery consent field. These do not make email mandatory for purchasing. UniShop2 receives a conditional script only on the UniShop2 checkout route; it injects a separate, initially unchecked opt-in and sends the four contact fields to a nonce-checked same-origin endpoint only when the user opts in. Opting out deletes the stored contact. Registered customers continue to use their customer account/newsletter consent handling.

Data is saved in a sidecar table scoped to the current store and session. Existing accounts, addresses, orders and UniShop2 checkout business logic are not modified. `lastname` was added to the sidecar table; existing installations migrate through an idempotent column check. Automatic emails still depend on cart activity, consent and mailer settings; a contact alone is not confirmation of email delivery. Contacts expire after seven days.

The optional UniShop2 script is delivered through CodeCart's common/header controller only when the feature is enabled; custom header replacements may require separate integration. Other third-party checkouts are not supported without an explicit bridge. Test on a backup/staging shop with both guest modes, registered customer checkout, rejection/revocation of consent, the store's SMTP, and actual orders before production activation.
