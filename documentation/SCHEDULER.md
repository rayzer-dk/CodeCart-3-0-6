# CodeCart PRO — Cron / Scheduler

## One server Cron

Preferred: run the `CLI` command copied from **Admin → Tools → Cron / Scheduler** once every 5 minutes. Use the PHP binary that runs the storefront. In your hosting panel configure minutes `*/5`, hours `*`, days `*`, months `*`, weekdays `*` and paste the displayed command. As an alternative, use the displayed HTTPS command. Never install both commands for the same scheduler, and keep the HTTPS key private.

## Three admin sections

- **Scheduled tasks**: choose a handler already installed in `catalog/controller/cron`, set its interval and enable/disable it. Code and route are technical identifiers generated by CodeCart. Editing a task preserves its protected settings. Manually running a disabled task requires confirmation.
- **External Cron**: paste a supported HTTPS curl/wget command provided by an extension; only an HTTPS Cron endpoint with a protected header is supported. CodeCart does not run shell commands. Imported jobs start disabled. The hosting helper generates the five timing fields for commands that should run on the hosting panel, rather than inside CodeCart.
- **Queue**: view and retry pending/failed jobs. The `core.queue.worker` scheduled task is the only automatic queue runner. Disabling it prevents automatic processing; `queue:run` remains an intentional manual command.

## Monitoring and status

Only server CLI and authenticated Web Cron calls update the server heartbeat. Manual operations and visitor-initiated heartbeats do not prove server Cron is configured. History records actual handler executions, with timestamp, source, status and duration, and is retained for approximately 30 days. A successful HTTP response from an external service confirms acceptance, not the business action inside that extension.

The schedule interval is a minimum delay between executions; a job cannot run more often than the main server Cron. Tasks with a 60-second interval will normally run at the next five-minute server Cron tick. Scheduler batches and queues report an error if any executed handler fails. The core database migration preserves administrator-customized system-task intervals and enabled/disabled states.

## Upgrade / diagnosis

Create and verify full backups of all site files and the database before updating. Apply files, let CodeCart's migration add the two observability tables, and validate one server-driven run. Check the server heartbeat and the journal for a recent `cli` or `web` entry. If the heartbeat is unavailable, verify the single hosting Cron job and the PHP executable independently. Do not disclose the Cron authentication key or encrypted arguments in support logs.
