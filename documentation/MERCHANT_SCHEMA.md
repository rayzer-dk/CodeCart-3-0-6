# CodeCart PRO — merchant structured data

## Scope

Settings for the **main store**: System → Settings → Edit main store → SeoPro → "Merchant identity, shipping and returns (Schema.org)".

Settings for **additional stores**: System → Settings → Edit store → "Merchant identity, shipping and returns (Schema.org)" tab.

Save with the existing OpenCart form Save button. Settings are stored per store in the existing `config` namespace (`config_codecart_schema_*`) and do not require SQL migrations. Other store settings and extensions are not modified.

The existing **Built-in Schema.org JSON-LD** switch controls ALL CodeCart-generated JSON-LD. It does not disable actual shipping methods, returns, URL rewriting, indexing, sitemaps or third-party markup.

## Merchant identity

`OnlineStore` always uses the existing store name, logo, phone, email and address. Optional legal name, VAT ID and real HTTPS social profiles supplement these fields. Do not use unrelated URLs in `sameAs`.

## ShippingService

Shipping is **OFF** until explicitly enabled and saved. To enable, enter a truthful fixed delivery rate (including 0 for unconditional free shipping), currency, destination countries (ISO2), handling day range and transit day range. These must represent one genuine unconditional store-wide shipping policy. A shipping information page may be selected for a policy URL. If the user changes to an incomplete or contradictory configuration, the save is rejected, and the storefront never publishes invalid shipping schema.

The separate OfferShippingDetails switch is **OFF** until explicitly enabled. It should only be enabled where exactly the same flat shipping conditions apply to **all physical products**, with no price variation by cart value, parcel weight, region or carrier. A product's `Offer` receives these data only when its currency is the same as the configured rate currency and the product is physical. This feature does not calculate checkout shipping prices.

For variable rates, discounts and customer-specific rules, use Google Merchant Center and the store's actual shipping extension. Do not advertise a fixed shipping cost that only applies to some orders.

## MerchantReturnPolicy

Returns are **OFF** until explicitly configured and enabled. Enter the applicable two-letter country codes and select the policy type: finite window, unlimited or not permitted (only if lawful). Finite returns require days since delivery. Optional return method and fee ownership are explicit. A charged return shipping fee requires an amount and ISO4217 currency.

Link the public information page that contains the actual written policy. If no separate return-policy page is selected, the store's existing return-terms information page is used as the link when set. A site-wide policy is published within `OnlineStore`; it is not automatically duplicated on every product `Offer`. Distinct product-level return policies require separate implementation and truthful exceptions.

## Multi-store and languages

The schema generator accepts a policy only if it was saved for the currently active `config_store_id`. This prevents the default store's rate or return policy accidentally appearing on an additional store. Country/currency codes and numeric rates are common to languages, and all policy-page URLs are generated by OpenCart URL routing in the visitor's language. Link each information page to all target stores and translate its content as appropriate.

## Verification

Run `php tools/structured-data-check.php` locally or see the "CodeCart source integrity" GitHub Action. Then verify page source on a homepage, physical product, digital product, another currency and an additional store in Google Rich Results Test. Ensure Merchant Center rates and return settings agree with the public site. Google may prioritize Merchant Center account policies over embedded markup.

Documentation: https://developers.google.com/search/docs/appearance/structured-data/shipping-policy and https://developers.google.com/search/docs/appearance/structured-data/return-policy

**Back up site files and database before deploying any update.**
