## Исправление безопасности

В исходном Build 1.9.12 неудачная запись новой сессии позволяла продолжить вход со старым ID. Тест воспроизвёл сохранение авторизации под старым ID. Исправление очищает данные и прекращает вход при false или исключении backend. Успешная ротация сохраняет авторизацию под новым ID. Регрессионный тест включён в release gate.

## Проверка обновлений

Использованы официальные исходники OpenCart с тегами 3.0.5.0 и 3.0.5.1, ocStore с тегом v3.0.4.1. Сначала установлен каждый исходный магазин, создана проверенная копия БД, затем наложены файлы CodeCart и запущен настоящий защищённый установщик обновления.

Сохранность проверена для товаров, категорий, тестового клиента, заказа, пользовательской настройки, SEO URL, активной темы, стороннего события и OCMOD. Для ocStore дополнительно выполнено прямое сравнение mysqli с восстановленной предшествующей БД: подозрение на потерю записей из промежуточного CLI-снимка не подтвердилось.

Во всех трёх сценариях прошли явная модернизация с подтверждённым backup, повторная модернизация, повторный шаг установщика и открытие витрины. После модернизации отсутствуют legacy engines/charsets и ошибки преобразования; блокирующих расхождений схемы нет. Существующая активная тема default сохранена.

Остались неблокирующие отличия унаследованной схемы: OpenCart — 37 предупреждений (8 типов колонок и 29 индексов); ocStore — 38 предупреждений (9 типов колонок и 29 индексов). Это преимущественно более короткие legacy-поля IP и отсутствующие дополнительные индексы. Их сохранение не означает полного совпадения БД с чистой установкой. Влияние дополнительных индексов на большой рабочий каталог отдельно не измерялось.

## Границы проверки

- Локальный runtime выполнен на PHP 8.3 и MariaDB 10.11; PHP 8.1–8.3 проверены release gate и регрессионными тестами. GitHub CI дополнительно подтвердил release gate на PHP 8.1–8.5 и commerce runtime на PHP 8.4 с MySQL 8.4 и MariaDB 10.11. Это покрытие конкретных тестов, а не гарантия всех сторонних интеграций.
- Оформление заказа проверено HTTP-запросами, без полного визуального и браузерного аудита интерфейса.
- Доставка писем, реальные платёжные API и все сторонние модули на пользовательском магазине не подтверждены.
- Предупреждения Composer о точных версиях пакетов сохранены: pinning используется намеренно вместе с lock.

Перед установкой или обновлением обязательно создать и проверить полный backup файлов сайта и базы данных. Веб-корень — только upload; инструменты tools и служебные файлы репозитория не должны публиковаться как часть витрины.
