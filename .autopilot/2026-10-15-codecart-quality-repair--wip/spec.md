# Исправления качества CodeCart

Классификация: bugfix, compatibility, тесты и комментарии. Профиль DEEP для проверки релиза; безопасность и commerce не изменять без доказанного дефекта. Работать в main. Не копировать коммерческие исходники UniShop2 в публичный репозиторий; использовать их локально как эталон для тестов.

1. Сохранить baseline, импортировать текущий пользовательский ZIP, проверить разницу и происхождение.
2. Переработать хрупкие проверки структуры таблицы/CSS/атрибутов и ложные заверения в сообщениях. Сохранять offline-тесты модели дат. Устранить ошибочную обработку PHP-комментариев в i18n-check.
3. Свести UniShop2-исправление к корректным точкам интеграции; проверить реальные операции оригинального OCMOD в обоих порядках, с casts, spaces/tabs и повторным refresh. Не делать лицензирование сторонней темы и не менять шифрованные файлы.
4. Просканировать все first-party PHP, Twig, JS, CSS, XML, JSON, SQL и docs, вложенные архивы; отделить vendor. Проверить синтаксис PHP8.1–8.3, Twig/JS/XML/JSON, BOM/UTF8, опасные конструкции, debug, временные фразы, дубли языков, читаемость и зависимости. Новые дефекты исправлять по первопричине; автонаходки просматривать, не удалять все комментарии.
5. Обновить версии выпуска согласованно, manifest и documentation ZIP, собрать проверенный архив без developer tools и без перезаписи старых релизов. Отдельный OCMOD compatibility-пакет должен иметь install.xml/upload/README и новую X.Y.Z версию.
6. Выполнить локальные проверки и подходящие CI workflows на точном коммите; записать PASS/FAIL/NOT RUN и реальные ограничения. В финале указать конкретные файлы, коммит, GitHub и архив.

Очистка CSS означает удаление служебного шума, а не переписывание каскада без визуальных регрессий. Общие службы PHP/DB и работающие сайты не останавливать.
